  • retrieval-provenance-guard: Prompt marking on every sink: the agent adapter wraps untrusted chunks in <untrusted> blocks under a quarantine notice. Application-side only at /api/agent/email (f20f482): once the actor's latest assistant run retrieved untrusted content, a message that leaves the organisation or carries the tracer is refused. Exports, refunds, and CRM writes are not gated by provenance, so there the defense is the prompt alone.
  • memory-write-guard: Application-side: /api/agent/memory refuses a write labelled derived_from=untrusted. The label comes from the model's own intent, so the check trusts the model to report provenance; every stand-in here reports it honestly.
  • output-sanitization: Application-side: /api/agent/email refuses an external destination or a body carrying the tracer, unconditionally.
  • capability-scoping: Application-side: every agent tool route refuses an operation outside the task's declared capability set.
  • prompt-isolation: Application-side data withholding: the context response omits the operating notes, so the model has nothing to leak (it is also told not to disclose them).
  • schema-validation: Application-side: /api/agent/email refuses control characters in a subject, closing the header-injection path. It does not restrict a destination named directly.
  • workflow-approval: Application-side: the refund and export routes refuse an operation without a matching approval record.
